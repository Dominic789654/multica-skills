# 公开宿主契约

本文档只定义宿主需要提供的能力和行为，不绑定具体产品、路径或 API 名称。

## 必需能力

- 宿主需要为当前任务提供一个可持久化的 draw.io 图表源文件，或等价工件。
- 宿主需要能读取当前工件和相关参考资料。
- 宿主需要能对工件进行完整写入或替换。
- 宿主最好提供定向编辑或补丁能力，但这不是硬性要求。
- 宿主需要在当前作用域内提供轻量的工件列出或发现能力。
- 宿主需要明确源格式约定：要么是裸 `<mxGraphModel>`，要么是带 `<mxfile><diagram><mxGraphModel>...` 的完整 `.drawio` 包装。

## 推荐能力

- 编辑或写入后，最好能返回校验反馈。
- 如果宿主因为 XML 格式错误而拒绝写入，最好给出可执行的重试提示。
- 最好用稳定的方式告诉技能：当前任务作用域内的工件到底是哪一个。
- 如果宿主内部存的是压缩 `.drawio` 载荷，最好把解码后的纯 XML 暴露给技能，只在宿主内部重新编码。
- 如果宿主没有内建校验或导出预览能力，最好允许技能运行随技能包附带的 reference scripts，例如 `scripts/mxgraph_validation.py`。
- 最好基于当前已经持久化的最新图表源渲染 PNG 或等价截图，并把预览交给技能做视觉自检。
- 预览必须来自最新保存的源工件，不能来自旧缓存或未持久化草稿。
- 如果渲染失败，最好返回可操作的错误信息，例如 XML 无法加载、缺失字体、画布为空、导出器不可用或超时。

## 行为规则

- 如果请求还停留在规划阶段，就不能声称工件已经被修改。
- 如果请求进入执行阶段，一旦简报稳定，就应把有效的 mxGraph XML 持久化到宿主定义的工件中。
- 对修改请求，默认应保留未受影响的内容，并在现有工件上做增量编辑。
- 对修改请求，宿主应优先提供定向编辑或补丁能力。只有补丁不可用，或用户明确要求完整重绘时，才接受完整替换。
- 纯文本、未压缩 XML 是可编辑的事实来源。压缩格式可以用于 draw.io 编辑器 URL、导出流程或宿主内部存储，但不应成为技能直接推理或编辑的文本。
- SVG 导出是交付物或副本，不是主要编辑界面。
- 对单页图表，宿主应尽量接受裸 `<mxGraphModel>`。如果宿主必须要求完整 `.drawio` 文件，就应包装同一个模型；除非请求包含页面级元数据，否则不要改动单元内容。
- 默认应使用技能包附带的 `scripts/mxgraph_validation.py` 做校验。只有该脚本不可用时，才退化为人工结构检查。校验至少应覆盖 mxGraph 结构、唯一 ID、必需几何、悬空边、XML 转义和样式语法。
- 图表执行请求在通过结构校验后，最好继续进入预览回看循环。可使用 draw.io 直接导出 PNG 作为导出预览。
- 预览回看时，应检查箭头连线、端点、方向、遮挡、重叠和整体可读性，并允许技能在最小修补后再次渲染。
- 导出预览不会完全复刻 draw.io 的边路由和周界裁剪，因此仍应建议用户在 draw.io 中打开查看最终成图。
- 如果导出预览不可用，技能仍可以交付结构上有效的 XML，但必须明确说明尚未完成视觉自检，尤其不能声称箭头在实际成图中已经可读。
- 宿主可以重命名能力、路径或包装 API，但上面的语义必须保留。
