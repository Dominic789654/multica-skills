# 渲染视觉自检 Rubric

用于 draw.io / mxGraph 图表在写入并通过结构校验后的视觉闭环。这里的优先目标不是让图表“更漂亮”，而是发现 XML 校验看不出的成图问题，尤其是文字与图形的对应关系、箭头、端点、重叠，以及紧凑度和可读性之间的失衡。

## 输入

- 当前已持久化的 draw.io / mxGraph 源工件。
- 由 draw.io 导出的 PNG 预览。
- 用户原始需求和本轮修改范围。

不要只靠脑内想象判断成图。导出预览不复刻 draw.io 的边路由与周界裁剪，箭头与标签的最终位置仍以在 draw.io 中打开后的结果为准。

## 审查顺序

1. 箭头和连线：先检查所有关系是否连接到正确节点、方向是否正确、箭头头部是否可见。
2. 结构语义：检查用户要求的节点、阶段、分支、反馈、泳道和容器关系是否完整。
3. 文字与图形关系：检查文本标签、说明、图例与其对应节点、边、图标或图片区块的相对位置是否清楚。
4. 布局可读性与紧凑度：检查是否有重叠、遮挡、截断、跑出画布、过度交叉、阅读顺序混乱，或明显还能收紧却没有收紧的留白。
5. 标签和样式：检查字号、对比度、标签换行、边标签位置和整体视觉一致性。

## 箭头优先检查项

- 每条边的 `source` 和 `target` 与业务语义一致。
- 箭头方向符合阅读顺序；横向流程通常从左到右，纵向流程通常从上到下，反馈边必须明确区别于主路径。
- 箭头头部没有被目标节点、容器边框、标签或其他连接线遮挡。
- 箭线路径应足够直接；除非为避让冲突所必需，不要出现无意义绕路、回折或让关系显得暧昧的走线。
- 连接线不会穿过关键节点正文；跨泳道或跨容器连线应能看出起点和终点。
- 并行边、分支边和回路边彼此可区分，不应重叠成一条无法判断的线。
- 边标签不压住箭头头部，不让源/目标关系变得模糊。
- 对新增、删除或移动节点后的图，确认没有视觉上的“孤儿线”、残留线段或指向空白区域的箭头。

## 连线修补顺序

- 先判断问题是“空间不够”还是“路由不稳”。如果边被迫贴字、贴标题带或埋进节点，先调整受影响节点、簇间距或容器节奏，腾出走线走廊。
- 当问题集中在长回路、跨容器或跨泳道、跨分区回传或并行边互相压住时，给该边补 1 到 2 个中继点，让路线先离开源节点，再沿空白带转向，最后进入目标节点。
- 只有当箭头持续从错误一侧进入、总被周界裁剪吞掉，或默认路由反复贴错边时，才固定 `exitX` / `exitY` 或 `entryX` / `entryY`；不要一开始就把所有边端口都写死。
- 标签问题最后处理：先把线走顺，再移动标签或补 `labelBackgroundColor`；不要试图靠标签位置掩盖错误路由。

## 文字与图形关系检查项

- 文本标签、编号、说明与对应节点、边、图标或图片区块的归属清楚，读者无需猜测文字在说明什么。
- 边标签应贴近对应连线，但不能压住箭头头部、覆盖节点正文，或漂移到其他边上造成误指。
- 分区标题、图例和容器标签应紧贴其所属区域，不能因为局部移动而落入相邻区域。
- 当图中同时存在图片、图标、截图或示意图时，说明文字不遮挡关键图像内容，且与所说明对象保持稳定、可辨认的相对位置。

## 布局与紧凑度检查项

- 不要用重叠、贴边、压窄节点或压缩字号来换取紧凑；紧凑只能来自去掉无意义留白、缩短不必要的线段或收紧局部间距。
- 如果主路径、相关支路或配套说明之间存在大块无信息空白，且可通过局部平移或缩短连线消除，就应视为需要修补。
- 紧凑后的布局仍应保留清楚的阅读节奏：主路径、分支、反馈和图片区块之间要有足够间距，让人一眼分辨层次。

## 通过标准

全部满足时，才可停止渲染迭代：

- 结构校验通过，且渲染图不是空白、截断或明显比例错误。
- 用户要求的关键元素全部可见，并保持正确相对关系。
- 所有关键箭头的端点、方向和箭头头部都清楚可辨。
- 文字、标签、图例和对应图形或图片区块的归属清楚，没有因位置错位而误导阅读。
- 主阅读路径没有被交叉线、回路、容器边框或标签打断。
- 节点、边标签、标题和容器标签没有明显重叠、遮挡或截断。
- 布局已经收紧到没有明显无效留白，同时仍保留可读宽度、间距和边界留白。
- 本轮修补没有破坏用户要求保留的 ID、样式、坐标或连接关系。

## 迭代策略

- 每轮只做能解释清楚的最小修补，例如移动节点、调整局部间距、收紧无效留白、对齐说明文字、改连接端点、增加 `jettySize`、移开边标签、改变局部路由或补充缺失箭头样式。
- 默认最多 3 轮：生成/编辑后渲染为第 1 轮，修补后最多再做 2 轮。
- 如果仍存在严重箭头错误，但每轮都有明确改善，可以扩展到 5 轮。
- 如果连续两轮没有改善，停止并报告剩余问题和可能需要的人工处理。
- 如果导出预览不可用，不要执行伪视觉审查；报告已完成 XML/结构检查，以及视觉风险未被实际验证。
